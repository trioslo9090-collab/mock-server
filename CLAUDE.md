# Mock Server для OpenAPI 3 — Правила проекта

## Описание проекта
Локальный mock-сервер для OpenAPI 3 спецификаций, написан на Python.

## Окружение и инструменты

### ОС и оболочка
- **ОС**: Windows
- **Оболочка**: PowerShell
- **Виртуальное окружение**: `.venv` (уже создано)
- **Python**: `.venv\Scripts\python`

### Стек технологий
- **Веб-фреймворк**: FastAPI + uvicorn
- **Парсинг конфигов**: PyYAML
- **Генерация данных**: Faker
- **Тестирование**: pytest, httpx
- **Управление зависимостями**: requirements.txt (все зависимости фиксируются)

## Правила разработки

### TDD-подход (обязателен)
1. **Сначала тесты**: Написать тест для новой функциональности
2. **Убедиться, что тесты падают**: Запустить `pytest` и подтвердить, что тесты не проходят
3. **Только потом — код**: Написать реализацию, чтобы тесты прошли

### Работа с тестами
- **Никогда не изменяй тесты для прохождения**: Если тест не проходит — меняй код, не тесты
- **Никогда не удаляй тесты**: Все написанные тесты — часть спецификации проекта
- **Регрессионные тесты при багах**: Найдя баг, сначала написать тест, который его выявляет, потом исправить код

### Поиск и исправление багов
1. **Найти root cause**: Понять, почему происходит проблема
2. **Объяснить**: Описать найденную причину
3. **Регрессионный тест**: Написать тест, воспроизводящий баг
4. **Исправить**: Написать код, который исправляет проблему
5. **Проверить**: Убедиться, что регрессионный тест теперь проходит

### Итеративная разработка
- Работай **маленькими шагами**
- После каждого успешного прогона тестов предложи **git commit**
- Коммиты должны быть атомарными и сфокусированными на одной задаче

## Команды для запуска тестов

```powershell
# Запуск всех тестов с кратким выводом
.venv\Scripts\python -m pytest -q

# Запуск конкретного теста
.venv\Scripts\python -m pytest -q tests/test_file.py::test_function

# Запуск с подробным выводом
.venv\Scripts\python -m pytest -v

# Запуск с покрытием кода
.venv\Scripts\python -m pytest -q --cov
```

## Управление зависимостями

- Все зависимости должны быть указаны в `requirements.txt` с **фиксированными версиями**
- При добавлении нового пакета: `pip install package_name` → обновить `requirements.txt`
- Перед коммитом убедиться, что все зависимости актуальны

## Git коммиты

- Маленькие, атомарные коммиты после каждого зелёного прогона тестов
- Понятные сообщения коммитов, описывающие что было сделано
- Формат: `feature: описание` / `fix: описание` / `test: описание` / `refactor: описание`
